# Shared Six-Step Discovery Framework

This framework is common across all four pillars (DWA, AP/AR, Print, PDF). Each pillar reference file applies it with pillar-specific inputs and angles — this file is the canonical version.

## Step 1 — Gather Two Critical Inputs

Before doing anything, the seller needs:

1. **The account being pitched** (specific company name)
2. **The scenario** — specific context, use case, or opportunity being addressed

If either is missing, **ask before proceeding**. Don't generate generic content.

Accept any input form: free text, pasted email threads, meeting notes, call summaries, RFP excerpts. Be flexible.

Pillar-specific add-ons (collect when relevant):
- **AP/AR**: invoice volume, ERP system, key AP/AR pain points
- **Print**: fleet size, print server count, VPN dependency, compliance posture
- **PDF**: current PDF tool, user count and mix (power vs occasional), licensing model, pain points

## Step 2 — Research the Account Externally

Use publicly available sources. Don't fabricate — if you cannot verify, say so.

Common sources:
- Analyst presentations and investor days
- Earnings calls and quarterly transcripts
- Public filings (10-K, 10-Q, annual reports)
- Press releases and news coverage
- Industry commentary and analyst reports
- Company website, careers page (signals on hiring priorities), recent announcements

What to look for varies by pillar (see the pillar reference for the focused list). General signals to find:
- The client's current technology stack and key vendors
- Recent strategic announcements (M&A, transformations, leadership change)
- Regulatory or compliance pressures specific to their industry
- Public stumbles — failed initiatives, integration challenges, security incidents

## Step 3 — Review Internal Positioning Materials

Match the account and scenario to:
- **Industry-specific angle** — does an existing Industry Solutions story apply?
- **Value-based narrative** — is there an Outside-In value proposal, ROI framework, or use case from the repository that fits?
- **Compliance-driven narrative** — does the client's geography or regulatory exposure unlock a specific compliance positioning?

**Always lead with value.** Value-based outcomes for the customer beat product features every time.

## Step 4 — Identify the Right Positioning Angle

Each pillar has a primary positioning frame:

| Pillar | Primary Frame |
|---|---|
| **DWA** | Build vs Buy + AI-ready data layer |
| **AP/AR** | Build vs Buy in AP context (ERP fallacy) |
| **Print** | Infrastructure Elimination |
| **PDF** | TCO (perpetual vs subscription) |

Each frame has two scenarios — the client already has a competitor solution (displacement) or has nothing in this space (greenfield). Apply the right one. See the pillar reference for specifics.

## Step 5 — Build Differentiation Around Core Pillars

Every positioning output must reinforce that pillar's four core differentiators. These are listed in each pillar reference under "Build Differentiating Position Around Core Pillars." Don't skip them — they are the consistent backbone that prevents positioning from drifting into generic pitches.

## Step 6 — Produce Output

Deliverable shape:
- **Primary**: executive-quality positioning brief, structured, value-led, account-specific
- **Audience-tailored**: select language, examples, and proof points for the stated audience (CIO ≠ CFO ≠ AP Director ≠ Procurement)
- **Specific**: name products, tiers, integrations, customers, numbers — never vague
- **Honest**: never fabricate customer outcomes or claim files exist that don't

If the seller asks for a deck or document, follow `deck-format.md` to produce markdown slide content. Point them at the live web app for branded `.pptx` / `.docx` output.

## When the Seller Steers in a Different Direction

The seller may pull the conversation in unexpected directions — battlecard mid-thread, switch from AP to DWA cross-sell, dive deep on one specific objection. Follow their lead while maintaining positioning quality. Don't insist on completing the six steps in order if they want to skip ahead — but don't generate generic content if the two critical inputs (account + scenario) are still missing.
