SECTION 1: APP CONCEPT & ARCHITECTURE
================================================================================

Build a content generator agent called "Tungsten Automation AI Positioning."
The output will be both Claude text from the interactive prompt and a PowerPoint
Deck + Word positioning document. The positioning will be different based on
which pillar the user selects.

There are 4 pillars:
1) DWA — Document & Workflow Automation
2) AP & AR — Accounts Payable & Accounts Receivable Automation
3) Print — Print Management & Output
4) PDF — PDF Productivity

The home page shows 4 large Netflix-type tiles, one for each pillar. The user
clicks on the pillar of choice and is presented with a Claude-based chat prompt
with sample suggested prompts. It uses Opus 4.6.

Each pillar page has:
- Left panel: Claude-powered chat interface (streaming, markdown rendering)
- Right panel: Content Generator that produces .pptx decks and .docx positioning documents
- The content generator MUST take the chat dialogue into context
- Chat sessions persist via localStorage so users can pick up where they left off
- Each pillar has its own chat history (pillar-aware storage keys)

SECTION 5: EXECUTIVE DECK BUILDER FRAMEWORK
================================================================================

Role & Lens:
You are a 30-year McKinsey veteran — a partner who has built and delivered
thousands of executive-level presentations. You think in frameworks but never
expose them. Every slide earns its place. Every word carries weight. White space
is a strategic choice, not wasted real estate.

Guiding Framework (invisible to the audience):
Structure around PISB — Problem, Impact, Solution, Benefit — but never label
these sections. The audience should feel the logic, not see the scaffolding:

1. Open with the customer's world. Demonstrate understanding of their industry
   dynamics, macro pressures, and specific dilemma. Use data, market context,
   and language that signals genuine research.

2. Make the stakes tangible. Quantify or illustrate the cost of inaction.
   Show empathy, not alarm.

3. Position solution through value-based outcomes. Don't lead with features.
   Lead with what changes for them.

4. Land on benefit with gravity. The close should feel inevitable, not salesy.
   The executive should think "they get us" before "they want to sell us something."

Formatting & Style Rules:
- Fewer words, more impact. If a bullet runs past one line, rewrite it.
- No bullet should merely inform — it should advance the argument.
- Max 3-4 content elements per slide. Let the slide breathe.
- Headlines must be assertive, insight-driven statements — not topic labels.
  (e.g., "Digital labor costs rising 3x faster than output" not "Cost Overview")
- Strip filler: "leverage," "synergies," "holistic," "best-in-class"
- Every slide must pass the "so what?" test.

Supplementary Research Folders:
- Industry Solutions Folder: vertical-specific use cases, proof points, customer examples
- Value Engineering Folder: ROI models, TCO analyses, calculation methodologies
Pull selectively. Only include material that directly reinforces the story arc.

SECTION 13: TECHNICAL NOTES
================================================================================

- Next.js 16 / Turbopack, React 19, TypeScript, Tailwind CSS v4
- Tailwind v4: custom colors MUST use @theme {} in globals.css (tailwind.config.ts colors are silently ignored)
- AI SDK v6: @ai-sdk/react useChat, DefaultChatTransport, UIMessage.parts
- @ai-sdk/anthropic v3: requires explicit baseURL: "https://api.anthropic.com/v1"
- Model ID: claude-opus-4-6 (not claude-opus-4-0-20250115)
- React infinite loop prevention: useEffect must depend on primitives (messageCount, lastMessageId), not array references
- Python scripts for PowerPoint (.pptx) and Word (.docx) generation
- python-pptx cannot open .potx directly — must copy to temp .pptx first
- Python stdin must use io.TextIOWrapper(sys.stdin.buffer, encoding="utf-8") for UTF-8 on Windows
- Chat persistence via localStorage with pillar-aware keys
- Port: 3004 (dev server)
